OPA-FSO 仿真平台 · 使用说明书

多模块 · 点进去即可仿真VS Code + 原生 HTML

一、平台简介

本平台基于 6 篇光学相控阵（OPA）自由空间光通信（FSO）文献，用纯原生 HTML / CSS / JavaScript 搭建，无需安装任何专业仿真软件。平台共 6 个仿真模块，每个模块对应一篇论文的核心复现，并统一提供三个标签页：

  • 交互仿真：拖动滑块/点击按钮即可实时计算并绘制方向图、光斑、眼图、训练曲线等；
  • 理论分析：论文原理、公式（KaTeX 排版）、关键参数与结论；
  • 使用说明：该模块的具体操作步骤与预期结果。

界面主题（浅色高级版）

平台采用“浅色控制台 + 深色仪器屏幕”的高级科研软件配色：导航、首页、参数控制面板、文档与表格为浅灰蓝底 + 白色卡片 + 柔和阴影，明亮且长时间使用不刺眼；三维场景、光斑 / 热图、眼图与终端日志保留深色背景——这是刻意设计，光束与光斑只有在深色“屏幕”上才最清晰，相当于软件里嵌入的一台台显示器 / 示波器；各类方向图、收敛曲线、BER 曲线则为浅色图表，坐标轴与网格已按浅色优化。如需在深浅色间切换，只需修改 assets/css/style.css 顶部 :root 中的颜色变量，即可全站统一生效。

三、如何运行（三种方式，任选其一）

方式 A：VS Code + Live Server（最推荐）

  1. 用 VS Code 打开整个 opa-fso-platform 文件夹（File → Open Folder）；
  2. 左侧扩展商店搜索并安装 “Live Server”（作者 Ritwick Dey）；
  3. 在资源管理器找到 index.html，右键 → “Open with Live Server”；
  4. 浏览器自动打开 http://127.0.0.1:5500/index.html，即平台首页。

方式 B：Python 内置服务器（无需装扩展）

  1. 在 opa-fso-platform 文件夹地址栏输入 cmd 回车，打开命令行；
  2. 执行：python -m http.server 8000；
  3. 浏览器访问 http://localhost:8000/。

方式 C：直接双击（不推荐）

直接双击 index.html 会以 file:// 方式打开。本平台大部分页面可显示，但部分浏览器对本地脚本/资源有安全限制，可能出现图表不渲染等问题，请优先用方式 A 或 B。

重要：转发或拷贝给他人时，请连同 assets 文件夹（含 style.css、common.js）与 modules、docs 整个目录一起发送，仅发单个 HTML 会丢失样式与物理引擎。

六、动态三维场景使用指南 NEW

每个模块都新增了「三维场景」标签（与 交互仿真 / 理论分析 / 使用说明 并列）。它用 Three.js 在三维空间中把 OPA 的波束控制、跟踪与通信过程“演”出来，并提供 8 种可随时切换的通信场景：5 类基础场景——直接协同（障碍通信）、多跳中继 Mesh（自动寻路）、自由空间（开阔远距）、有限空间（室内/舱内）、密集障碍通信；以及 3 个指令驱动的链式中继场景（2 / 3 / 4 台 OPA，两至四跳接力）。系统实时计算每条链路 / 每一跳的通断与通信质量。

1. 如何打开

进入任一模块 → 点击顶部标签栏的「三维场景」，即可看到三维画面并自动开始仿真，无需任何配置。

2. 视角操作（鼠标）

  • 左键拖动：环绕场景旋转视角；
  • 滚轮：放大 / 缩小；
  • 右键拖动：平移视角；
  • 「重置视角」按钮可一键回到默认机位。

3. 场景里有什么

  • OPA 设备（3–5 台，数量随场景）：含底座、支架、可转向云台、发光发射面与透镜阵列，头部会实时转向并跟踪目标，顶部有编号标签；
  • 接收终端：一架带旋翼的无人机，按设定轨迹飞行；
  • 障碍物：墙 / 柱 / 悬空板，数量与布局随场景；中继与障碍场景还含可来回移动的动态遮挡板；
  • 光束：直连场景为每台 OPA 到无人机一条光束；中继场景光束在 OPA 之间逐跳连接、末跳到终端，并用淡青色细线显示所有可用 mesh 邻接。

4. 遮挡检测与链路切换

系统对每条光束做实时射线检测：光束与障碍物相交即判为非视距（NLOS）——光束只画到障碍物表面并变红、断链，接收功率骤降约 45 dB、BER 趋近 0.5；无遮挡时为视距（LOS），光束为模块主题色。系统在所有视距 OPA 中自动选择接收功率最高的一条作为活动链路（HUD 中标 ACTIVE），活动链路变化时左上角提示“切换 → PAT#x”，体现多 OPA 协同的冗余与越障能力。

5. 左上角 HUD 读数

  • 每条链路：编号、LOS / NLOS / ACTIVE 徽标、距离 (m)、接收功率 (dBm)、BER；
  • 活动链路接收功率、系统 BER；
  • 模块专属指标（见下表）。

6. 右侧控制面板（全部可调，实时生效）

  • 通信场景模式：在 8 种场景间切换，切换后自动重建 OPA 布局、障碍物与相机；
  • 目标运动模式：自动巡航 / 手动控制；手动时出现 X / Y / Z 三个滑块直接定位无人机；
  • 轨迹类型：圆形巡航、8 字利萨如、矩形巡逻、多航点穿梭；
  • 目标速度、轨迹范围 R、飞行高度：滑块调节（范围随场景自动调整）；
  • 发射功率 Pt：影响所有链路 / 每一跳的接收功率与 BER；
  • 大气衰减(天气)：仅自由空间 / 中继场景出现，模拟晴到雾天的大气损耗（dB/km）；
  • 动态遮挡物开关（障碍 / 中继场景）：开启后遮挡板来回移动；直接协同场景另有遮挡物位置滑块；
  • 暂停 / 继续：冻结运动便于观察或截图。

八种场景对照：

场景特点主要观察 / 指标
直接协同 · 障碍通信4 台 OPA 直连终端，静态墙 + 1 动态板遇障变红断链、自动选最佳 OPA（ACTIVE）
多跳中继 Mesh5 台 OPA，源在远处、直连被建筑遮挡 / 距离过远Dijkstra 自动寻路、逐跳 HOP、端到端 BER、冗余邻接
自由空间 · 开阔远距3 台 OPA、无遮挡、距离数十至上百米路径损耗 + 大气衰减，近的 OPA 质量好
有限空间 · 室内/舱内封闭小房间，OPA 在四角高处，隔断 / 机柜短距（4–10m）、隔断遮挡频繁
密集障碍通信4 台 OPA + 两块正交运动遮挡板部分 OPA 变红断链、其余维持，频繁切换
两跳中继 · 2 台 OPA源直连终端被建筑遮挡，仅 1 台中继可同时连通源与终端指令：源→中继→终端，红色直连、端到端 BER
三跳中继 · 3 台 OPA源经 2 台中继沿弧线绕过中央建筑3 跳 HOP、端到端 BER、各跳误码累积
四跳中继 · 4 台 OPA源经 3 台中继沿 Z 字折线绕过遮挡，终端缓慢移动4 跳 HOP、端到端 BER、中继覆盖与误码权衡
两类中继的区别：「多跳中继 Mesh」由系统用 Dijkstra 在所有可用链路中自动寻路，并显示冗余邻接，链路断了会自动改道；「两 / 三 / 四跳中继」是指令驱动的确定性路由——系统明确命令源 OPA 把信号发给指定中继逐跳转发，红色光束是源直连终端的失败尝试，若指定的某一跳真的被挡则报“链路中断 @ HOP k”而不自动改道，便于观察中继协议本身。

七、常见问题 FAQ

1. 图表区域空白 / 一直 loading？

多为 CDN 未加载：检查网络；用 Live Server（http://）而非 file:// 打开；刷新页面。可按 F12 看 Console 是否有报错。

2. 公式显示成原始 LaTeX 源码？

KaTeX 未加载完成，刷新页面即可；确认网络能访问 cdn.jsdelivr.net。

3. M3 训练要多久？

“快速演示”约几秒；“开始训练”默认参数约十几秒到半分钟，属正常（模拟真实神经网络训练），期间 Loss 图实时更新。

4. 页面数字和论文不完全一样？

平台在浏览器内用解析物理模型复现论文核心规律，部分模块为降尺度演示（如 M3 用 16 阵元），数值口径在各模块“理论分析”中已注明；趋势与结论与文献一致。

5. Live Server 端口 5500 被占用？

VS Code 会自动改用 5501 等；或在 Live Server 设置里改端口。

6. 中文乱码？

确认编辑器以 UTF-8 保存（VS Code 右下角可查看/切换编码），浏览器编码为 UTF-8。

八、技术与数据说明

  • 纯前端、无后端、无账号、不收集数据；所有计算在本地浏览器完成；
  • 图表用 ECharts 5.5，光斑/热图/眼图用 Canvas，公式用 KaTeX 0.16，三维场景用 Three.js r128，均经 jsDelivr CDN 引入；
  • 公共物理函数集中在 assets/js/common.js，可复用三维引擎在 assets/js/scene3d.js（window.OPA3D.mount），详见《实现路径》文档；
  • 辐射效率热图、FPGA 时序等为基于文献结果的示意性重建，用于教学演示，非实时全波/电路仿真。
建议学习路径：首页 → M1（理解波束指向与跟踪）→ M2（相干合成与通信指标）→ M3/M5（智能/优化算法）→ M4/M6（集成器件与高速控制）。配合各模块“理论分析”标签，可形成从原理、算法到器件系统的完整认知。
